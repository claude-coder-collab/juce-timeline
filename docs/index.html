jtimeline and jwaveform

JUCE 8 modules for displaying an audio timeline: tracks of clips with waveform previews, bound to an application's own data model.

  • jwaveform: builds, caches and draws waveform peaks. Usable on its own.
  • jtimeline: the timeline component. Depends on jwaveform.

The timeline is read-only for now: it displays, navigates and selects. Editing is planned.

Setup

Requires JUCE 8 and C++23. Add both modules with CMake:

juce_add_module(path/to/juce-timeline/modules/jwaveform)
juce_add_module(path/to/juce-timeline/modules/jtimeline)
target_link_libraries(MyApp PRIVATE jtimeline jwaveform)

jwaveform uses juce_audio_formats and juce_gui_basics. Include <jtimeline/jtimeline.h> or <jwaveform/jwaveform.h>.

Concepts

  • Time is in samples: SamplePosition (int64) at the sample rate the model reports. SampleRange is half-open, [start, end).
  • Ids: TrackId, ClipId and MarkerId are enum class types over uint64_t, chosen by the model. Nothing is index-based except track order.
  • Sources must be at the timeline sample rate. A clip's timeline position p plays source sample sourceOffset + (p - start). Sample-rate conversion is the model's job.
  • Overlapping clips on one track are allowed; the model's draw order decides which is on top.
  • A clip is either ClipKind::audio or ClipKind::group. A group stands for clips the model keeps elsewhere and has no waveform or fades.

jtimeline

Model

A TimelineModel is a struct of std::function callbacks. The view pulls only what it shows and caches it. Everything the callbacks capture must outlive the binding.

jtimeline::TimelineNotifier notifier;                    // owned by your model
jtimeline::Timeline timeline;

timeline.setModel({
    .trackIds     = [&] { return myTrackIds(); },        // display order
    .trackInfo    = [&](jtimeline::TrackId id) { return myTrackInfo(id); },
    .clipsInRange = [&](jtimeline::TrackId id, auto start, auto end) { return myClips(id, start, end); },
    .clipInfo     = [&](jtimeline::ClipId id) { return myClipInfo(id); },
    .sampleRate   = [&] { return 48000.0; },
    .length       = [&] { return myLength(); },
    .notifier     = &notifier,
});
CallbackReturns
trackIds()Tracks in display order.
trackInfo(TrackId)optional<TrackInfo>: name, colour, height hint. Empty if the track does not exist.
clipsInRange(TrackId, start, end)Clips with clip.start < end && clip.start + clip.length > start, in draw order (later on top). Must not scan the whole track; keep clips sorted by start.
clipInfo(ClipId)optional<ClipInfo>: kind, track, start, length, source offset, name, colour, gain (dB), fades, muted, optional WaveformSource.
sampleRate()The timeline sample rate.
length()The timeline end, in samples.
adjacentClip(TrackId, ClipId, Direction)Optional. Previous or next clip in start order. Speeds up keyboard navigation.
clipSpans(TrackId, start, end, minGap)Optional. Occupied spans, merged where closer than minGap. Speeds up zoomed-out drawing. mergeSpans() helps implement it.
markersInRange(start, end)Optional. Markers with start <= position < end, sorted. Ranges may extend outside [0, length()].
timelineSelection()Optional. A range the model owns, such as the play or loop range.

A model missing a required callback shows as empty. Pass an empty TimelineModel to unbind.

Reporting changes

Call notifier.changed(change) on the message thread after modifying the model. Every view bound to the model updates.

notifier.changed(jtimeline::ClipsChanged{ .ids = { movedClip, removedClip } });
notifier.changed(jtimeline::TracksChanged{});
notifier.changed(jtimeline::MarkersChanged{});           // markers or timeline selection
notifier.changed(jtimeline::FullReset{});                // includes sampleRate() or length()

ClipsChanged covers added, removed, moved and edited clips; list removed ids too. Without a notifier, call timeline.refresh() instead. If the notifier is destroyed first, its views detach and show as empty.

Waveforms

Set ClipInfo::source and give the timeline a shared cache:

auto cache = std::make_shared<jwaveform::PeakCache>();
timeline.setPeakCache(cache);                            // share between views

info.source = jwaveform::WaveformSource{
    .key = path + juce::String(modificationTime),
    .createReader = [&formats, path] {
        return std::unique_ptr<juce::AudioFormatReader>{ formats.createReaderFor(juce::File{ path }) };
    },
};

Peaks are built in the background and drawn as they arrive. Missing files, read errors and sources at another sample rate are shown on the clip as labels. See Peak cache for the factory's rules.

View control

timeline.setVisibleRange({ .start = 0, .end = 48000 * 30 });
timeline.zoomToFit();
timeline.scrollTo(position);
timeline.setPlayhead(position);                          // cheap; call from a timer while playing
timeline.setFollowPlayhead(true);                        // page when the playhead leaves the view
timeline.setWaveformScale(2.0);
timeline.setTrackHeight(track, 112);

Zoom ranges from 16 pixels per sample to the whole timeline (getZoomLimits()).

CallbackCalled when
onTimeClicked(position)The ruler is clicked or dragged, or anywhere in overview mode.
onPlayStop()Space is pressed. Playback is up to the application.
onSelectionChanged()Selected clips, tracks or time range change.
onViewChanged()Zoom or scroll changes.
onWaveformScaleChanged()The view's or a track's waveform scale changes.

Selection

Each view has its own selection of clips, tracks and a time range. It is kept by id across model changes; ids that disappear are dropped.

timeline.onSelectionChanged = [&] { showInspector(timeline.getSelectedClips()); };

timeline.getSelectedClips();                             // sorted by id
timeline.getSelectedTracks();                            // display order
timeline.getTimeSelection();                             // optional<SampleRange>
timeline.setSelectedClips(clips);
timeline.selectClip(clip, jtimeline::SelectMode::toggle);
timeline.clearSelection();

Users select by clicking, rubber-band dragging, dragging on the ruler and with the keyboard (see Input bindings). Selecting clips also selects their tracks. Visible clips are exposed to screen readers.

Overview strip

Bind a second Timeline to the same model and switch it to overview mode. It shows the whole timeline in compact form and reports clicks through onTimeClicked.

overview.setModel(model);
overview.setPeakCache(cache);
overview.setOverviewMode(true);
main.onViewChanged = [&] { overview.setHighlightedRange(main.getVisibleRange()); };
overview.onTimeClicked = [&](auto position) { main.scrollTo(position); };

Customising

  • Colours: Timeline::ColourIds, set on the timeline, a parent or the look and feel.
  • Drawing: derive your LookAndFeel from jtimeline::TimelineLookAndFeelMethods as well and override what you need, such as drawTimelineClip, drawTimelineRuler or getTimelineMetrics.
  • Track headers: subclass TrackHeader to add controls. Headers are pooled and rebound as tracks scroll; update contents in trackChanged().
  • Ruler labels: setRulerFormatter. The default is h:mm:ss.mmm.
struct MyHeader : jtimeline::TrackHeader
{
    MyHeader() { addAndMakeVisible(mute); }
    void trackChanged() override { mute.setToggleState(isMuted(getTrackId()), juce::dontSendNotification); }
    void resized() override { mute.setBounds(getLocalBounds().removeFromRight(28).reduced(4)); }
    juce::ToggleButton mute;
};

timeline.setTrackHeaderFactory([] { return std::make_unique<MyHeader>(); });

jwaveform

Peak cache

PeakCache builds multi-resolution peaks on background threads, once per source key, and keeps them within a memory bound (default 256 MB). Share one cache across all views.

jwaveform::PeakCache::Options options;
options.memoryLimitBytes = std::size_t{ 512 } * 1024 * 1024;
options.threads = 2;
auto cache = std::make_shared<jwaveform::PeakCache>(options);
  • The key identifies the audio. Include something that changes when the file does, such as its modification time.
  • createReader runs on background threads, possibly several at once, and must return a new reader per call, or nullptr if the audio cannot be opened.
  • At high zoom, the raw samples on screen are read through the same factory, so keep it valid while the source is shown.
  • For peaks you already have, set WaveformSource::peaks instead; the key and factory are then ignored.

WaveformView

A component showing one source, without a timeline.

jwaveform::WaveformView view;
view.setPeakCache(cache);
view.setSource({ .key = key, .createReader = factory });
view.setVisibleRange(startSample, endSample);            // empty range = whole source
view.setStyle({ .channelMode = jwaveform::ChannelMode::combined });

Colours come from WaveformView::ColourIds. getState() reports loading, ready, cannotOpen or readError.

Custom drawing

Request a handle and draw from it in your own component. The handle keeps the build alive; onChange is called on the message thread as peaks arrive.

handle = cache->request(source, [this] { repaint(); });

void paint(juce::Graphics& g) override
{
    auto data = handle.getData();
    if (data == nullptr)
        return;

    jwaveform::WaveformStyle style{ .colour = juce::Colours::lightblue };
    auto spp = (end - start) / getWidth() / g.getInternalContext().getPhysicalPixelScaleFactor();
    jwaveform::RawSamples samples;
    if (jwaveform::usesRawSamples(*data, spp))
        samples = handle.getSamples(jwaveform::rawRangeFor(start, end));

    jwaveform::drawWaveform(g, getLocalBounds().toFloat(), *data, start, end, style, samples);
}

Drawing costs one column per physical pixel. Partial peaks draw as far as they go.

Threading

  • All model callbacks, TimelineNotifier::changed and all cache and view methods are called on the message thread.
  • The only exception is WaveformSource::createReader, which is called on background threads.
  • Peak handles may outlive the cache.
